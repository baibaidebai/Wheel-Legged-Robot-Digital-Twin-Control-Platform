# 轮腿机器人孪生控制系统需求文档

## 项目简介

轮腿机器人孪生控制系统是一个基于ROS2的仿真控制平台，用于《轮腿机器人孪生控制方法的研究》大创项目。系统通过数字孪生技术实现对串联轮腿机器人的仿真控制，为后续硬件集成和强化学习算法研究提供基础平台。

## 术语表

- **数字孪生系统 (Digital_Twin_System)**: 基于物理模型的虚拟机器人仿真控制系统
- **轮腿机器人 (Wheel_Legged_Robot)**: 具有轮子和腿部关节的混合移动机器人
- **关节控制器 (Joint_Controller)**: 负责机器人关节位置控制的软件模块
- **仿真环境 (Simulation_Environment)**: Gazebo物理仿真世界
- **控制面板 (Control_Panel)**: 用户交互界面，用于发送控制指令和监控状态
- **状态同步器 (State_Synchronizer)**: 负责虚实状态同步的核心模块
- **IMU传感器 (IMU_Sensor)**: 惯性测量单元，提供姿态和加速度数据
- **URDF加载器 (URDF_Loader)**: 统一机器人描述格式文件解析和加载模块

## 需求

### 需求 1: 机器人模型加载与可视化

**用户故事**: 作为研究人员，我希望能够加载现有的轮腿机器人URDF模型并在3D环境中可视化，以便进行仿真实验。

#### 验收标准

1. 当系统启动时，URDF加载器应当让用户选择现有的模型并加载位于`src/robot/urdf/`目录下的机器人模型
2. 当URDF文件加载成功时，仿真环境应当在Gazebo中显示完整的轮腿机器人3D模型
3. 当模型显示时，数字孪生系统应当正确渲染所有关节（lf0_Joint, lf1_Joint, rf0_Joint, rf1_Joint）和轮子（l_wheel_Joint, r_wheel_Joint）
4. 当用户查看模型时，系统应当显示机器人的质量分布、惯性参数和碰撞边界
5. 如果URDF文件损坏或缺失，系统应当显示错误信息并提供故障排除建议

### 需求 2: 关节位置控制

**用户故事**: 作为控制工程师，我希望能够通过ROS2话题发送关节位置指令，以便控制机器人的运动姿态。

#### 验收标准

1. 当用户通过ROS2话题发布关节位置指令时，关节控制器应当接收并解析指令
2. 当接收到有效的关节角度值时，数字孪生系统应当在仿真环境中执行相应的关节运动
3. 当关节运动时，系统应当遵守URDF中定义的关节限制（effort=30N·m, velocity=1000rad/s）
4. 当发送超出关节限制的指令时，系统应当将指令限制在安全范围内并记录警告
5. 当关节到达目标位置时，系统应当发布关节状态反馈信息

### 需求 3: IMU数据仿真与显示

**用户故事**: 作为算法开发者，我希望获取机器人的IMU传感器数据，以便开发姿态控制算法。

#### 验收标准

1. 当机器人在仿真环境中运动时，IMU传感器应当生成实时的姿态、角速度和线性加速度数据
2. 当IMU数据生成时，系统应当通过ROS2话题`/imu/data`发布sensor_msgs/Imu消息
3. 当控制面板运行时，系统应当实时显示IMU数据的数值和可视化图表
4. 当机器人静止时，IMU应当显示重力加速度（约9.8m/s²）和零角速度
5. 当仿真物理参数改变时，IMU数据应当相应地反映物理状态变化

### 需求 4: 用户控制界面

**用户故事**: 作为操作员，我希望有一个直观的图形界面来控制机器人和监控状态，以便进行实验操作。

#### 验收标准

1. 当系统启动时，控制面板应当显示包含关节控制滑块和状态监控区域的主界面
2. 当用户拖动关节控制滑块时，系统应当实时发送对应的关节位置指令
3. 当机器人状态更新时，控制面板应当实时显示当前关节角度、IMU数据和系统状态
4. 当用户点击"复位"按钮时，系统应当将所有关节恢复到初始位置（0度）
5. 当发生错误时，控制面板应当在状态栏显示错误信息和时间戳

### 需求 5: 虚实状态同步模拟

**用户故事**: 作为系统架构师，我希望实现虚实状态同步功能的仿真版本，以便为未来硬件集成做准备。

#### 验收标准

1. 当仿真机器人状态改变时，状态同步器应当记录并存储状态变化历史
2. 当系统运行时，状态同步器应当模拟网络延迟和数据传输过程
3. 当状态同步时，系统应当比较"虚拟"和"实际"状态并计算同步误差
4. 当同步误差超过阈值时，系统应当触发状态校正机制并记录事件
5. 当用户查询时，系统应当提供状态同步质量报告和统计数据

### 需求 6: 数据记录与回放

**用户故事**: 作为研究人员，我希望能够记录实验数据并回放，以便分析机器人行为和验证算法。

#### 验收标准

1. 当用户启动记录功能时，系统应当开始记录所有关节状态、IMU数据和控制指令
2. 当记录进行时，系统应当将数据以ROS2 bag格式保存到指定目录
3. 当用户选择回放文件时，系统应当加载历史数据并在仿真环境中重现机器人运动
4. 当回放过程中，系统应当提供播放控制功能（播放、暂停、快进、倒退）
5. 当数据导出时，系统应当支持CSV格式导出以便后续数据分析

### 需求 7: 系统配置与参数调节

**用户故事**: 作为系统管理员，我希望能够配置系统参数和仿真设置，以便适应不同的实验需求。

#### 验收标准

1. 当系统启动时，系统应当从配置文件加载仿真参数（物理引擎设置、传感器参数等）
2. 当用户修改配置时，系统应当验证参数有效性并应用新设置
3. 当配置无效时，系统应当使用默认值并显示警告信息
4. 当系统关闭时，系统应当保存当前配置到文件以便下次启动使用
5. 当需要恢复时，系统应当提供恢复默认配置的功能

### 需求 8: 基于URDF的轮腿混合运动数字孪生映射器

**用户故事**: 作为项目负责人，我希望系统包含基于URDF的轮腿混合运动数字孪生映射器作为核心独创性功能，以便满足软件著作权申请要求。

#### 验收标准

1. 当系统解析URDF时，数字孪生映射器应当自动识别轮腿混合机构的运动学约束
2. 当处理闭环机构时，映射器应当建立轮子接触约束与腿部关节运动的耦合关系模型
3. 当执行运动映射时，系统应当实现从关节空间到任务空间的双向运动学转换
4. 当轮腿协调运动时，映射器应当确保运动一致性并处理奇异位形
5. 当用户查看时，系统应当提供运动映射可视化和约束违反检测功能

### 需求 9: 性能与稳定性

**用户故事**: 作为质量保证工程师，我希望系统具有良好的性能和稳定性，以便支持长时间实验。

#### 验收标准

1. 当系统运行时，仿真频率应当保持在至少50Hz以确保实时性
2. 当长时间运行时，系统内存使用应当保持稳定，无明显内存泄漏
3. 当处理大量数据时，系统响应时间应当在100ms以内
4. 当发生异常时，系统应当能够自动恢复而不需要重启
5. 当系统负载较高时，系统应当优雅降级而不是崩溃

### 需求 10: 控制算法验证平台

**用户故事**: 作为算法研究员，我希望系统能够支持多种控制算法的集成和验证，以便进行控制理论研究和算法对比。

#### 验收标准

1. 当系统运行时，算法管理器应当支持动态加载和切换不同的控制算法模块
2. 当使用强化学习算法时，系统应当提供标准的环境接口（符合OpenAI Gym规范）
3. 当实现LQR控制器时，系统应当提供状态空间模型和代价函数配置接口
4. 当开发自定义控制算法时，系统应当提供标准的控制器基类和接口规范
5. 当算法运行时，系统应当记录控制性能指标并提供算法对比分析功能

### 需求 11: 扩展性与兼容性

**用户故事**: 作为软件架构师，我希望系统具有良好的扩展性，以便未来集成硬件和新功能。

#### 验收标准

1. 当需要添加新传感器时，系统应当支持通过配置文件添加而无需修改核心代码
2. 当硬件接入时，系统应当提供标准的硬件抽象接口
3. 当使用不同ROS2版本时，系统应当兼容Humble和Foxy发行版
4. 当部署到不同平台时，系统应当支持Ubuntu 20.04和22.04操作系统
5. 当集成第三方库时，系统应当通过标准接口集成而不影响核心功能
